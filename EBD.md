# Seasonal eBird data for route quizzes

This is a local design and SQL prototype. AviQuiz has not imported the full release or enabled route quizzes. Keep archives, staging databases, and event-level extracts outside Git and the web deployment.

## What was inspected

The September 2026 downloads are uncompressed GNU tar containers. The main archive contains one 248,557,679,868-byte gzip member (~231.5 GiB); the sampling archive contains one 8,542,876,270-byte gzip member (~8.0 GiB). Both include metadata v1.16, protocol and region lookup files, a citation, and terms. The gzip members contain tab-separated text with 52 named observation fields and 33 named sampling fields. They can be read directly from tar without writing the decompressed files. The workspace had about 46 GiB free at inspection; don't plan on a full extraction there.

A 500,000-row prefix from each member had consistent field widths, but the prefixes did not cover the same observation years: the main prefix was 2012 and the sampling prefix was 2026. The main prefix contained 1,751 Colombia rows, and the sampling prefix contained 3,521 Colombia rows. Neither is a representative sample, and they cannot be joined to estimate a site's reporting rate. The 2012 records included edits from October 2026; the release label is not a safe edit cutoff. This inspection did not check the full gzip checksums or establish global ordering.

The paired March 2025 Tuscaloosa County sample was used to exercise the schema: all 4,863 observation rows joined to their sampling records via `SAMPLING EVENT IDENTIFIER`. Of 317 sampling rows, 243 qualified as complete stationary/traveling submissions, representing 202 distinct events after grouping. Counting approved species-level rows only for this format check, the query returned 119 species across 31 sampled days and correctly indicated insufficient seasons. This validates the join and query, not a calibrated likelihood model. The next real-data pilot should use paired, matching Colombia subsets across several years (start with Chicaque and a sparse stop), plus Chatham County as a challenge case. Prefer regional downloads if available for both files, to avoid inflating unrelated worldwide data just to select those areas.

## Reproduce a local pilot

Use [`scripts/ebd-seasonal-pilot.py`](scripts/ebd-seasonal-pilot.py) with paired regional `.txt`, `.gz`, or eBird Custom Download `.zip` inputs. For a zip containing both files, pass it to both flags. The runner reads only approved species-level detections, complete stationary/traveling lists, and the chosen region or locality; it intentionally has no further effort caps or subspecies rollup. It reports aggregate counts, day-balanced and raw ranks, and recurrence tiers. The `--focus` species includes daily detection totals. Without `--observations`, only effort is reported. Point `--rankings` outside the repository. Do not use this script to attest that a subset is complete: verify release and scope, and finish any worldwide streaming step before passing its projected output.

```sh
python3 scripts/ebd-seasonal-pilot.py \
  --observations /path/to/regional.zip --sampling /path/to/regional.zip \
  --place US-NC-037 --first-year 2017 --last-year 2025 --release relSep-2026
```

## What we keep

[`schema/ebd-seasonal.sql`](schema/ebd-seasonal.sql) stores a denominator per **place × local date** (number of eligible independent complete checklists), plus sparse species detections at the same grain (number of those checklists reporting each species). Both are replaceable by place and observation year, with release, taxonomy, processing-policy and geography provenance. This retains the daily evidence needed to recompute seasonal summaries and identify concentrated reports, without a serving table of observers, original checklists, free-text comments, exact personal-location points, or counts of individual birds. Start with selected hotspots and regions; measure daily table size before expanding. Precompute compact season summaries for serving if needed. Choose the analytical and serving database after measuring the regional pilot; the reference SQL uses SQLite.

- **Place:** match an exact hotspot by locality ID, an administrative region by region code, or later a versioned grid cell or boundary. Compute each place directly from events. Do not add overlapping hotspot, cell, and region aggregates. A broader fallback is a separate labeled result, not additional evidence for the narrower site. Route stops carry their own dates; combine their resulting species lists by species identity without adding or multiplying stop rates.
- **Effort:** join to sampling rows on `SAMPLING EVENT IDENTIFIER`. Require complete eligible lists; start with stationary and traveling, then validate effort limits. Keep eligible sampling events with no matching observations, but track that count and reconcile quality omissions before publishing rates. A non-report is a non-detection. Deduplicate shared outings using a namespaced `GROUP IDENTIFIER` or the event ID if unshared. Count a species at most once per outing. For the pilot, union approved detections from eligible shared copies that agree on the assigned place and date, and flag conflicting groups rather than merging across dates/locations silently.
- **Species:** accept approved observations, map identifiable infraspecific taxa to species using a versioned crosswalk, and exclude unresolved slashes, spuhs, and hybrids from exact species questions. An `X` count is a detection. Do not use `REVIEWED=1` as the inclusion rule. Use the release taxonomy and crosswalk it separately to AviQuiz media/answer IDs; a taxonomy split/lump can require a rebuild.

## Querying a visit and handling rarities

[`schema/ebd-seasonal-query.sql`](schema/ebd-seasonal-query.sql) reads one place, one taxonomy and processing policy, a historical observation-year range, and an inclusive month/day window. The caller chooses a narrow seasonal window first; if coverage is thin, widen it or explicitly query a broader geography. Across New Year, group December and January under the same season start year. For a complete wrapped window use only historical ranges with both halves available; the query counts sampled seasons and days, not seasons for which every calendar date was covered. For a current or partial release, the caller should choose completed seasons or label partial coverage. An empty species result is not evidence of absence; check eligible effort separately.

- **Raw checklist rate** = complete checklists reporting the species ÷ eligible complete checklists. Cornell's bar charts use checklist frequency, not total individuals or raw sighting rows. A heavily chased rarity can still appear on a disproportionate number of complete checklists. [Cornell bar chart documentation](https://support.ebird.org/en/support/solutions/articles/48001255130-ebird-bar-charts-and-graphs).
- **Day-balanced rate** = mean of each sampled day's reporting rate, counting days with eligible effort and no reports as zero. A day with 100 checklists no longer carries ten times the weight of a day with 10. This still won't distinguish a bird that stays for weeks from many individuals; also compare the number of seasons in which the species was reported against seasons with sampling.
- **Default ranking candidate:** rank recurring species ahead of single-season records, then by day-balanced rate. Keep single-season records visible in an optional rare/uncertain tier. With only one sampled season, say evidence is insufficient and avoid an automatic rarity exclusion. The two-season rule is an initial signal, not a universal cutoff; sparse sampling, recent colonization, or truly localized species can all yield only one observed season. Use the Colombia and Chatham pilots to pick minimum effort, lookback and any shrinkage or incident-clustering rule. Display as reporting evidence, not a visitor's encounter probability.

In a synthetic check with six sampled dates over three seasons, a rarity reported on 98 of 150 checklists beat the regular species' 30 of 150 by raw rate. Day balancing reversed them (~28% vs. ~43%). The rarity's two reporting dates crossed New Year but represented one season; it ranked below the recurring species. This is a simulated chase, not a measurement of Chatham's Kirtland's Warbler.

## Updating without a worldwide rebuild

**Don't store just a lifetime count and latest sighting date.** That loses the denominator, seasonal history and the ability to subtract a changed record. Separate the source release and edit time from the observation date used for season. Cornell documents updated EBD releases and separate sampling files; no authoritative change feed with deletion markers was established for these archives. [Cornell download documentation](https://support.ebird.org/en/support/solutions/articles/48000838205-download-ebird-data).

1. **Baseline:** stream both members (or paired region extracts); validate headers by name, row widths, IDs and join coverage. Stage only necessary projected fields on disk, partitioned by region, and produce daily facts. Don't assume row order or join the streams by position. Record the source release, exact regional/date scope, row counts/reject counts and policy version. Do not retain raw comments or observer identity in the analytical store.
2. **First refresh strategy:** rebuild only selected regional partitions from an authoritative newer paired extract. Replace affected place/year partitions transactionally, including now-empty partitions, with both numerator and denominator together. Keep old facts until the new ones pass integrity, coverage and large-change checks. Use a transaction across affected years/places if an event can move between them, and reconcile overlap with the extraction boundary. Refreshing just recent years is a performance tradeoff: corrections to older years remain stale until re-reconciled. Unchanged partitions do not need recomputing, but determining that a partition truly is unchanged requires a reliable delta or a comparable complete extract. If only the worldwide gzip is available, filtering may still require a sequential full scan; this schema does not provide random access to it.
3. **Record-only refresh, if supported:** require a reliable feed for both observations and sampling updates, including removals, or compare complete scoped snapshots. Keep a private minimal reconciliation ledger keyed by `GLOBAL UNIQUE IDENTIFIER` and `SAMPLING EVENT IDENTIFIER`, with prior normalized species/event/group contributions and edit versions. For a change, reload the affected outing (including shared copies), remove its old contribution, and add its new one; refresh both old and new place/date partitions as needed. Apply a release once and advance checkpoints only after commit. An edit-time watermark with overlap can capture visible upserts, including backdated observations; it cannot discover deletions, visibility changes, or records moved outside a filtered extract by itself. This delta ledger and feed integration are future work, not implemented by the aggregate SQL.

The archive citation is *eBird Basic Dataset. Version: EBD_relSep-2026. Cornell Lab of Ornithology, Ithaca, New York. Sep 2026.* Retain source citations and apply the actual permission terms to any future publication. Group deduplication is based on the field meanings in [Cornell's auk documentation](https://cornelllabofornithology.github.io/auk/reference/read_ebd.html).

## Shared route tester

AviQuiz’s `/routes` page uses a compact, versioned catalog generated by `python3 scripts/build-route-pilot.py /path/to/aggregate-pilot-output`. It contains place labels, fixed seasonal windows, ranked species, and season counts. It includes neither event-level records nor personal locations. The preset stops include Chatham County and Jordan Lake dam (September 20–October 10), Chicaque and Charca de Guarinocito (December), and Hotel Tinamú, Río Blanco’s lodge and upper reserve, and Hotel Termales del Ruiz in Caldas (February). Each window pools 2017–2025; February 29 is valid only in leap years. The existing December practice checklist and its site targets are separate.

A share link contains a validated snapshot in the URL fragment, which the browser does not send to the Worker. Recipients with existing Site access can take the visual quiz or make an editable copy. There is no public directory, permanent server record, owner identity, revocation, or account requirement. A new edit yields a new link; previously shared snapshots remain usable while their catalog version is supported. The public pilot accepts only catalog stops and curated targets from a small list of common species; curated targets have no site association or calculated reporting rate. Sensitive targets and private routes are outside the pilot. Route questions leave existing learning statistics unchanged. The one-season option includes rarities and one-time sightings as well as regular birds with limited reports.
